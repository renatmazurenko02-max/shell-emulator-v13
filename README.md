# Эмулятор оболочки. Вариант 13

Практическая работа: эмулятор командной оболочки с графическим интерфейсом.
Текущая реализация: этапы 1, 2 и 3. Этапы 4 и 5 не реализованы.

## Требования и запуск

Windows, Python 3.10 или новее с Tkinter. Сторонние пакеты не требуются.
Сборка не требуется. Из папки проекта:

```powershell
py -3 scripts/create_fixtures.py
py -3 -m src.main
```

Также можно открыть `run.bat`. Для проверки Tkinter: `py -m tkinter`.

## Реализованные возможности

- Графическое окно с именем VFS в заголовке.
- Ввод команд кнопкой или клавишей Enter, журнал ввода и ответов.
- Разбор аргументов с кавычками и подстановка `$NAME` и `${NAME}`
  из окружения реальной ОС.
- Заглушки `ls [путь]` и `cd [путь]`, показывающие имя и аргументы.
- Команда `exit` без аргументов закрывает окно.
- Сообщения о неизвестной команде, неверных аргументах и кавычках.

Имя VFS берётся из параметра `--vfs`, по умолчанию `generated/minimal.zip`.
Перед первым запуском создайте архивы командой выше. Архив загружается
только в память, папки на диске из архива не создаются.
Файлы и каталоги реальной ОС командами эмулятора не изменяются.

## Правила разбора

Это ограниченный учебный синтаксис, а не полная реализация Bash.
Аргументы сначала разделяются с учётом кавычек, затем в каждом
раскрываются переменные. Значение переменной сохраняется одним аргументом.
Раскрытие действует и для текста, изначально заключённого в одинарные
кавычки. Неопределённая переменная заменяется пустой строкой.
Пустой путь и опции, начинающиеся с `-`, отклоняются.
Для Windows-путей при ручном вводе используйте `/`, например `C:/Users`.
Конвейеры, перенаправления и запуск внешних программ не поддерживаются.
Пустая команда игнорируется.

## Проверка в окне

Введите по очереди:

```text
ls
cd /documents
ls "my documents"
ls $USERPROFILE
ls ${USERPROFILE}
unknown
ls a b
cd -x
ls "unfinished
exit now
exit
```

Первые пять команд показывают ответы заглушек. `$USERPROFILE` раскрывается
в путь из окружения Windows; `$HOME` можно использовать, если эта переменная
задана в ОС. Следующие команды показывают ошибки. Последняя закрывает окно.
Скрипт не проверяет существование пути: `ls` и `cd` пока являются заглушками.

## Этап 2. Параметры и стартовый скрипт

```powershell
py -3 -m src.main --vfs generated/minimal.zip --startup examples/success.txt
```

| Параметр | Назначение |
| --- | --- |
| `--vfs PATH` | Физический путь к ZIP с VFS |
| `--startup PATH` | Путь к текстовому файлу с командами |
| `--help` | Справка по запуску без открытия окна |

Оба пути разрешаются относительно текущей папки запуска и показываются
в окне полностью. Имя файла VFS отображается в заголовке.
Без `--startup` запускается только интерактивный режим.
Формат скрипта: UTF-8 (допускается BOM), одна команда на строку.
Пустые строки пропускаются, комментарии в скриптах не поддерживаются.
Каждая исполняемая команда и её ответ выводятся в окно.
Первая ошибка останавливает скрипт с указанием файла и номера строки;
окно остаётся открытым и позволяет вводить команды вручную.
Ошибки чтения и кодировки также показываются в окне.
Команда `exit` останавливает скрипт и закрывает окно.
Ошибочные параметры запуска показываются в PowerShell до создания окна.

### Сценарии демонстрации

- `examples/success.txt`: успешные команды, кавычки, окружение Windows.
- `examples/error.txt`: неизвестная команда; следующая не выполняется.
- `examples/arguments-error.txt`: неверные аргументы; следующая не выполняется.
- `examples/exit.txt`: завершение из скрипта.
- `scripts/check_success.bat`: оба параметра и пути с пробелами.
- `scripts/check_errors.bat`: ошибки команд и отсутствующий файл скрипта.
- `scripts/check_options.bat`: справка, ошибки параметров, значения
  по умолчанию, параметры по отдельности и выход из скрипта.

В каждом BAT-файле несколько последовательных запусков. Закрой текущее
окно эмулятора, чтобы перейти к следующему запуску. Для ручной проверки:

```powershell
py -3 -m src.main --vfs generated/minimal.zip --startup examples/error.txt
```

Ожидается ошибка на строке 2; `cd /must-not-run` не должна появиться
в журнале. После ошибки проверь ручной ввод команды `ls`.

## Этап 3. Виртуальная файловая система

ZIP читается через `zipfile` в режиме чтения. Папки сохраняются в множестве,
а содержимое файлов в словаре с абсолютными виртуальными путями.
Все файлы, включая двоичные, хранятся как строки base64. Чтение декодирует
их обратно в байты. Пустые файлы и пустые папки сохраняются.
Родительские папки восстанавливаются, даже если в ZIP нет отдельных записей
для них. После загрузки обращения к виртуальным файлам идут только в память.
Исходный архив не изменяется и не распаковывается.

Не допускаются пути с выходом через `..`, абсолютные имена записей,
конфликт файла и папки, повторяющиеся файлы. При ошибке загрузки окно
сообщает причину и не запускает стартовый скрипт. Заглушки и `exit`
остаются доступны, диагностические команды сообщают, что VFS не загружена.

### Служебные команды для демонстрации

Эти команды добавлены для проверки этапа 3. Они не заменяют полноценную
реализацию `ls` и `cd`, которая относится к этапу 4.

| Команда | Результат |
| --- | --- |
| `vfs-info` | Количество файлов и папок, список виртуальных путей |
| `vfs-read /путь` | Размер файла в байтах и его содержимое в base64 |

Диагностические пути отсчитываются от виртуального корня. Относительные
имена тоже трактуются относительно корня. `cd` пока не меняет каталог.

### Тестовые архивы и сценарии

`scripts/create_fixtures.py` создаёт архивы в `generated/`:

- `minimal.zip`: один текстовый файл.
- `multiple.zip`: несколько файлов, двоичные данные, пустой файл,
  имя с пробелами и пустая папка.
- `deep.zip`: три вложенных уровня папок с файлами на каждом уровне.
- `vfs with spaces.zip`: имя архива с пробелами.
- `broken.zip` и `unsafe.zip`: намеренно ошибочные примеры.

Архивы не добавляются в Git согласно требованиям оформления. Вместо них
хранится воспроизводимый генератор. Его повторный запуск перезаписывает
только перечисленные тестовые архивы в `generated/`.

```powershell
py -3 scripts/create_fixtures.py
py -3 -m src.main --vfs generated/deep.zip --startup examples/deep.txt
py -3 -m src.main --vfs generated/multiple.zip --startup examples/binary.txt
py -3 -m src.main --vfs generated/minimal.zip --startup examples/vfs.txt
```

`examples/vfs.txt` показывает все команды-заглушки и служебные команды,
переменные, кавычки и остановку на отсутствующем виртуальном файле.
`examples/exit.txt` проверяет выход. Ошибки проверяются отдельными
сценариями: после первой ошибки следующие команды не выполняются.

`scripts/check_vfs.bat` последовательно запускает три корректных варианта.
`scripts/check_vfs_errors.bat` проверяет повреждённый, небезопасный
и отсутствующий архивы. Закрывайте каждое окно для следующего запуска.
Сценарии второго этапа также обновлены для использования реальных ZIP.
