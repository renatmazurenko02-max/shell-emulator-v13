# Эмулятор оболочки. Вариант 13

Практическая работа: эмулятор командной оболочки с графическим интерфейсом.
Текущая реализация: этапы 1 и 2 из запланированных этапов 1-3.

## Требования и запуск

Windows, Python 3.10 или новее с Tkinter. Сторонние пакеты не требуются.
Сборка не требуется. Из папки проекта:

```powershell
py -3 -m src.main
```

Также можно открыть `run.bat`. Для проверки Tkinter: `py -m tkinter`.

## Реализованные возможности

- Графическое окно с именем VFS в заголовке.
- Ввод команд кнопкой или клавишей Enter, журнал ввода и ответов.
- Разбор аргументов с кавычками и подстановка `$NAME` и `${NAME}`
  из окружения реальной ОС.
- Заглушки `ls [путь]` и `cd [путь]`, показывающие имя и аргументы.
- Команда `exit` без аргументов закрывает окно.
- Сообщения о неизвестной команде, неверных аргументах и кавычках.

Имя VFS берётся из параметра `--vfs`, по умолчанию `demo-vfs.zip`.
Архив пока не требуется и не загружается: это реализуется на этапе 3.
Файлы и каталоги реальной ОС командами эмулятора не изменяются.

## Правила разбора

Это ограниченный учебный синтаксис, а не полная реализация Bash.
Аргументы сначала разделяются с учётом кавычек, затем в каждом
раскрываются переменные. Значение переменной сохраняется одним аргументом.
Раскрытие действует и для текста, изначально заключённого в одинарные
кавычки. Неопределённая переменная заменяется пустой строкой.
Пустой путь и опции, начинающиеся с `-`, отклоняются.
Для Windows-путей при ручном вводе используйте `/`, например `C:/Users`.
Конвейеры, перенаправления и запуск внешних программ не поддерживаются.
Пустая команда игнорируется.

## Проверка в окне

Введите по очереди:

```text
ls
cd /documents
ls "my documents"
ls $USERPROFILE
ls ${USERPROFILE}
unknown
ls a b
cd -x
ls "unfinished
exit now
exit
```

Первые пять команд показывают ответы заглушек. `$USERPROFILE` раскрывается
в путь из окружения Windows; `$HOME` можно использовать, если эта переменная
задана в ОС. Следующие команды показывают ошибки. Последняя закрывает окно.
Скрипт не проверяет существование пути: `ls` и `cd` пока являются заглушками.

## Автоматические тесты

```powershell
py -3 -m unittest discover -s tests -v
```

Либо откройте `test.bat`. Тесты проверяют движок без открытия окна:

## Этап 2. Параметры и стартовый скрипт

```powershell
py -3 -m src.main --vfs "fixtures/demo-vfs.zip" --startup examples/success.txt
```

| Параметр | Назначение |
| --- | --- |
| `--vfs PATH` | Физический путь к будущему ZIP с VFS |
| `--startup PATH` | Путь к текстовому файлу с командами |
| `--help` | Справка по запуску без открытия окна |

Оба пути разрешаются относительно текущей папки запуска и показываются
в окне полностью. Имя файла VFS отображается в заголовке.
Без `--startup` запускается только интерактивный режим.
Формат скрипта: UTF-8 (допускается BOM), одна команда на строку.
Пустые строки пропускаются, комментарии в скриптах не поддерживаются.
Каждая исполняемая команда и её ответ выводятся в окно.
Первая ошибка останавливает скрипт с указанием файла и номера строки;
окно остаётся открытым и позволяет вводить команды вручную.
Ошибки чтения и кодировки также показываются в окне.
Команда `exit` останавливает скрипт и закрывает окно.
Ошибочные параметры запуска показываются в PowerShell до создания окна.

### Сценарии демонстрации

- `examples/success.txt`: успешные команды, кавычки, окружение Windows.
- `examples/error.txt`: неизвестная команда; следующая не выполняется.
- `examples/arguments-error.txt`: неверные аргументы; следующая не выполняется.
- `examples/exit.txt`: завершение из скрипта.
- `scripts/check_success.bat`: оба параметра и пути с пробелами.
- `scripts/check_errors.bat`: ошибки команд и отсутствующий файл скрипта.
- `scripts/check_options.bat`: справка, ошибки параметров, значения
  по умолчанию, параметры по отдельности и выход из скрипта.

В каждом BAT-файле несколько последовательных запусков. Закрой текущее
окно эмулятора, чтобы перейти к следующему запуску. Для ручной проверки:

```powershell
py -3 -m src.main --vfs demo-vfs.zip --startup examples/error.txt
```

Ожидается ошибка на строке 2; `cd /must-not-run` не должна появиться
в журнале. После ошибки проверь ручной ввод команды `ls`.
